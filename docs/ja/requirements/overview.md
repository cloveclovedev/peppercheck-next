# 概要

PepperCheckが何のために存在し、何を作るかを記述する。

## 問題提起

多くの人は、モチベーションの維持とタスクの完了に苦労している。従来のタスク管理サービスは、次の理由でうまくいかないことが多い。

1. 自分との約束は無視したり放棄しやすい
2. タスクの結果に対するフィードバックが不足している

## 事前調査・根拠

「根性論や意志力に頼らない 行動科学が教える 目標達成のルール」という書籍を読んだことがアプリ作成のベースになっている。

こちらの本で言及されている「Behavioural Insights Team, BIT」の論文などを整理して、統計的なデータに基づいた効果の推定と機能の設計は実施し直しても良いかも。

## 解決策

PepperCheckは、次を組み合わせてこれらの問題に対処する。

- 社会的責任感: レフェリーによるタスクレビューや催促メッセージが軽い社会的プレッシャーを作る
- 金銭的責任感: ユーザーはタスクの完了に向けて事前にお金を支払う
- 客観的フィードバック: タスクの完了基準を事前に設定し、レフェリーがタスク達成度を評価する

## 解決策を実現するためのPepperCheckの主要機能

- タスクとレフェリーのマッチング機能
- レフェリーからのタスク達成度フィードバック機能
- レフェリーからのタスク締め切り前の催促メッセージ機能
- レフェリー維持のための報酬機能（タスク実行者から支払われる）
- 良いフィードバックにインセンティブを持たせるための評価によるレビュー報酬アップ機能

### 代替手段と優位性

| 代替手段 | 優位性 |
|---|---|
| 一人で使う習慣化や記録の道具 | タスク達成のためのモチベーション向上 |
| 家族や友人に確認を頼む | 相手の負担を気にせず依頼できる |
| 同じ目標を持つ仲間の集まり | 自分で仲間を探さなくてもレフェリーが割り当てられ、確認が義務になる |
| 有料のコーチ | タスク1つの単位で、安く頼める |
| AIのコーチング | 生身の人間が見る。ただし、これが効くこと自体が前提である ([前提](#前提)) |

## 利用者

- タスク実行者: タスクを実行し成果を得たい人
- レフェリー: タスクの完了に向けた声かけ、成果の評価やフィードバックをして報酬を得る人

## 価値

### 前提

最後に人を動かすのは、生身の人間に報告する義務があること、生身の人間がフィードバックを返してくれることである。AIのコーチングでは、これの代わりにならない。

### 確かめ方

未記入。人間のフィードバックが効くと、何をもって言えるかを決める。

### 崩れる条件

AIのフィードバックが、生身の人間のそれと同じだけ人を動かすようになったとき、この製品の価値は消える。

## 参入障壁

### 参入障壁はソフトウェアではない

マッチング、証拠の提出、判定の流れは、誰でも作れる。作れないのは、確認を頼みたい人と、確認をしてもよい人が、同じ場所に十分な数いる状態である。

この製品で作るべきものは、機能ではなくコミュニティの活性度である。活性度は時間をかけないと積み上がらず、始めるのが早いほど有利になる。

### 模倣されても残るもの

- 集まった利用者と、その間のつながり
- レフェリーの評価の履歴。信頼できるレフェリーがいること

## 制約

### お金を預からない

PepperCheckは、利用者のお金を預からない。タスク実行者の支払いは、レビューが完了した時点で確定させる。先にお金を受け取って預かると、個人事業として提供できなくなるためである。
