# 要件定義書

要件の一覧とその根拠を記述する。具体的な設計は記述しない。

- [概要](overview.md): 問題提起、根拠、解決策、主要機能、利用者、価値、参入障壁、旧PepperCheckとの関係
- [用語集](glossary.md): この文書群で使う言葉の意味

次の文書は、中身ができたときに作る。

- `technology.md`: 技術要素。使う技術と外部サービス、それを選んだ理由
- `functional/<分類>.md`: 機能要件。分類ごとに1つ (タスク、証拠、判定、報酬と支払い、課金、通知など)
- `non-functional.md`: 非機能要件

## 要件のID

機能要件と非機能要件の1行ずつに、IDを付ける。

- 形は`{FR|NFR}-{CAT}-{No}`とする。例: `FR-TASK-01`、`NFR-SEC-01`
  - `FR`は機能要件、`NFR`は非機能要件
  - `CAT`は分類。機能要件は`functional/`のファイル名を大文字にしたもの (`task.md`なら`TASK`)
  - `No`は分類の中の2桁の連番
- 1つのIDは、真偽を確かめられる1つの決まりにする
- 番号は使い回さない。消すときは行を残して「廃止。<ID> に置き換え」と書く
- 実装済みかどうかは、この文書には書かない。要求Issueと、その受け入れの確認から分かるようにする
